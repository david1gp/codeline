# Dual SSO support

## Goal

Support Zitadel and Authworks OIDC SSO concurrently, verify both provider paths, and deploy the result through the repository-managed preview service.

## Decisions

- Keep the existing OIDC transaction, identity, membership, and session schemas; issuer already identifies the provider securely.
- Add explicit `OIDC_AUTHWORKS_*` and `OIDC_ZITADEL_*` provider namespaces while preserving existing single-provider `OIDC_*` and `ZITADEL_*` configuration compatibility.
- Use one shared callback URI. Select callback credentials from the transaction issuer, never from callback query input.
- Require `provider=authworks|zitadel` when multiple providers are configured; retain provider omission for a single configured provider.
- Validate each provider's own resource-owner organization ID, then map accepted provider organizations to one configured local Codeline organization external ID.
- Authorize sessions against memberships from any configured provider issuer.
- Show configured providers on the login page without exposing provider configuration details.
- Deploy only with the managed `bun run deploy` workflow and verify the combined preview service.

## Approach

- Normalize legacy and explicit provider environment variables into a provider registry at startup.
- Thread that registry through login, callback, authentication, and issuer-scoped organization mapping while preserving current security checks.
- Expose a minimal provider catalog for the login UI.
- Update managed environment validation, examples, and integration documentation.
- Add focused dual-provider tests before running the complete verification and deployment workflow.
